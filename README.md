# SafeCross: Crosswalk Safety and Traffic Analytics
 
**CraftifAI Embedded SF, Track A (PipeGen) | Problem: Traffic and Crosswalk Analytics**
 
Cities build crossings and signals but rarely have live data on how many pedestrians, cyclists and vehicles actually use them. SafeCross turns a fixed-camera crosswalk clip into counts, crossing events and risk alerts using a GPU pipeline generated by PipeGen.
 
**See, decide, act**
 
| Step | What | Where |
|---|---|---|
| See | Detection, tracking, virtual-line crossing, TensorRT FP16 | PipeGen export (`pipeline/`, `models/`) |
| Decide | Stats and rule-based suggestions over PipeGen's output | Dashboard logic (`SafeCross–Dashboard.html`) |
| Act | Dashboard alert feed, JSON event log, summary export | Dashboard + `out/` |
 
**Principle:** PipeGen is load-bearing. Detection, tracking, line-crossing and engine compilation all happen in the pipeline. Nothing in this repo runs its own inference; the dashboard only consumes PipeGen's JSON.
 
---
 
## Pipeline
 
Generated by PipeGen 0.5.1 and exported with a ready-to-run launcher.
 
```
file/RTSP/camera -> nvstreammux -> nvinfer (YOLO11s, TensorRT FP16)
  -> nvtracker (NvDCF, persistent IDs) -> nvdsanalytics (line crossing)
  -> nvcustomprocess (JSON metadata) -> OSD -> display / H.264 mp4
```
 
| Item | Value |
|---|---|
| Model | YOLO11s, COCO, 80-class head, 640x640 input |
| Precision | TensorRT FP16 (`models/yolo11s.fp16.plan`, ONNX included) |
| Classes kept | person, bicycle, car, motorcycle, bus, truck |
| Detector threshold | 0.3 confidence, NMS IoU 0.45 |
| Tracker | DeepStream NvDCF (`config_tracker.yml`) |
| Line | `crosswalk_line`, (520, 955) to (1490, 975) in 1920x1080 space |
| Built on | RTX 4050 Laptop GPU, TensorRT 10.3.0, x86_64, DeepStream 7.1 |
| Outputs | `out/metadata.json` (per-frame JSON), `out/output.mp4` (headless), live window |
 
If your GPU or TensorRT version differs from the build machine, `run.sh` rebuilds the engine from the shipped ONNX automatically (about a minute, once).

## Requirements
 
- NVIDIA GPU with driver 560.35.03 or newer
- Docker, with your user in the `docker` group
- NVIDIA Container Toolkit
- Nothing else. CUDA, TensorRT and DeepStream live in the container image (~35 GB, pulled once).

## Quick start
 
The clip is **not included** in the export, so you must pass `--input`.
 
```bash
# 1. Run the pipeline and write the JSON where the dashboard looks for it
JSON_OUT=./out/events.json ./run.sh --input /home/faulty/videos/crosswalk.mp4 --headless
 
# 2. Serve the folder and open the dashboard
python3 -m http.server 8000
# open http://localhost:8000/SafeCross–Dashboard.html
```
 
Drop `--headless` to get the live window with boxes, IDs, the line and counts.
 
### `run.sh` options
 
| Flag | Meaning |
|---|---|
| `--input <src>` | Video file, `rtsp://...` stream, or `/dev/videoN` |
| `--output <dir>` | Results directory (default `./out`) |
| `--headless` / `--display` | Force no window / force a window |
| `--rebuild` | Redo parser build and engine resolution |
 
Useful environment variables: `JSON_OUT`, `JSON_MIN_CONF`, `BITRATE`, `FORCE_SW_ENC`, `PG_GPU`, `CAM_*`. Only one run of the folder at a time is allowed.

## Dashboard
 
`SafeCross–Dashboard.html` is a single file, vanilla JS, no build step.
 
- Tries to fetch `out/events.json`; if it can't, it shows an embedded sample from a 60.76 s, 1920x1080, 50 fps run (3,039 frames).
- **+ Load events.json** lets you pick a PipeGen JSON file manually (works without a server, so use this if `fetch` is blocked on `file://`).
- Shows tracked objects per class, objects-in-view over time with a peak marker, vehicle share, and a crosswalk alert feed.
- **Export summary** downloads `safecross-summary.json`.
### How alerts are derived
 
The dashboard reads `analytics[].line_crossing_cumulative` from each frame and emits an event whenever the cumulative count rises. A crossing is flagged **risk** when a person who just crossed has a car, bus or truck bounding box within 80 px of theirs. This is a simple proximity heuristic over PipeGen's output, not a validated safety metric.

## Known limitations (read before judging the numbers)
 
- **Filename mismatch.** The pipeline writes `out/metadata.json` by default; the dashboard looks for `out/events.json`. Use `JSON_OUT=./out/events.json` (as above) or load the file manually.
- **Crossings are not per class.** The line-crossing counter is keyed by line name, so the "Crossings" total is across all configured classes. The per-class cards show *unique tracked objects*, not crossings. Per-class crossing counts would need a separate line per class or per-object `line_crossing` status aggregated by label.
- **Tracked objects can overcount.** Unique track IDs include ID switches and brief re-detections, so 494 "person" tracks in a 60 s clip is likely higher than the true number of distinct people.
- **Line is fixed to this camera view.** Coordinates are in 1920x1080 space. A different clip needs `line-crossing-crosswalk_line` edited in `pipeline/configs/config_analytics.txt`.
- **Suggestions are illustrative heuristics** on a short clip, not traffic engineering.
- **Python stats/rules service (`/api/stats`) is not in this repo yet.** The PRD describes one; at present the dashboard computes its stats in the browser.
